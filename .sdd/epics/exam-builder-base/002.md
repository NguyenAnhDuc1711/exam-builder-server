# T002: Domain entities + SQLAlchemy models + initial migration

## Context

Mọi task từ Phase 2 trở đi (auth, question bank, exam, submission) đều thao tác trên các bảng được định nghĩa ở đây. Schema phải đóng đúng 1 lần vì Alembic migration đầu tiên là nền cho mọi migration sau — sai sót ở đây (thiếu constraint, sai FK) sẽ lan sang toàn bộ epic.

## Description

Định nghĩa domain entities thuần Python (dataclass, không phụ thuộc SQLAlchemy) ở `app/domain/entities/`, và SQLAlchemy ORM models tương ứng ở `app/infrastructure/db/models/`. Viết migration Alembic đầu tiên tạo toàn bộ bảng. **Không có field `organization_id` ở bất kỳ bảng nào (NFR-3 — single-tenant).**

## Implementation Steps

1. Domain entities (dataclass, `app/domain/entities/`): `User(id, email, password_hash, role: Literal["admin","user"])`, `Question(id, text, image_url: str|None, options: list[Option])`, `Option(id, text, is_correct: bool)`, `Exam(id, title, question_ids: list[int])`, `ExamAssignment(id, exam_id, user_id, assigned_at)`, `Submission(id, exam_assignment_id, submitted_at, score)`, `Answer(id, submission_id, question_id, selected_option_id, is_correct)`.
2. SQLAlchemy models (`app/infrastructure/db/models/`) tương ứng 1-1 với entities ở trên, cộng thêm `RefreshToken(id, user_id, token_hash, family_id, revoked: bool, expires_at)` (theo AD-2, không có entity domain riêng vì đây là chi tiết hạ tầng auth, không phải domain nghiệp vụ).
3. Bảng liên kết `exam_question(exam_id, question_id, order)` — composite PK hoặc surrogate key + unique(exam_id, question_id).
4. Constraint bắt buộc: `question.options` phải có đúng 1 `is_correct=True` — enforce ở application layer (không enforce được thuần bằng DB constraint đơn giản), nhưng đảm bảo FK `option.question_id` NOT NULL, CASCADE DELETE khi xóa question.
5. Constraint bắt buộc cho single-attempt (chuẩn bị cho T020): `submission.exam_assignment_id` UNIQUE — một assignment chỉ có tối đa 1 submission.
6. Constraint cho không gán trùng: `exam_assignment` UNIQUE(exam_id, user_id).
7. `app/infrastructure/db/session.py`: SQLAlchemy engine + sessionmaker đọc `DATABASE_URL` từ config (T001).
8. Chạy `alembic revision --autogenerate -m "initial schema"`, review file migration sinh ra, đảm bảo có đủ toàn bộ bảng + constraint ở trên trước khi apply.

## Acceptance Criteria

- **NFR-3 / scenario:** Given toàn bộ model đã định nghĩa, when review schema, then không có field/bảng nào chứa `organization_id` hoặc bất kỳ khái niệm multi-tenant nào.
- **FR-6 (chuẩn bị) / scenario:** Given bảng `submission` có unique constraint trên `exam_assignment_id`, when insert 2 submission cùng `exam_assignment_id`, then insert thứ 2 bị DB từ chối bằng `IntegrityError`.
- **FR-5 (chuẩn bị) / scenario:** Given bảng `exam_assignment` có unique constraint trên `(exam_id, user_id)`, when insert 2 assignment giống nhau, then insert thứ 2 bị từ chối.

## Tests to Write

- Migration test: `alembic upgrade head` chạy thành công trên DB rỗng, `alembic downgrade base` rollback sạch không lỗi.
- Constraint test: insert trùng `exam_assignment(exam_id, user_id)` → `IntegrityError`.
- Constraint test: insert trùng `submission.exam_assignment_id` → `IntegrityError`.

## Technical Details

Domain entities KHÔNG import SQLAlchemy — đây là ranh giới AD-1 bắt buộc, để `app/domain/` test được hoàn toàn độc lập với DB thật (dùng entity giả trong unit test của use case sau này).
